# 创作与反馈

本流程适用于不同主体、系列、画风和编辑任务。具体视觉标准来自本次要求与选用预设；通用规则负责准确组织输入、执行、验收和控制迭代。

## 本次目标

区分必须满足的要求、允许自行设计的部分，以及已有成果中需要保留的内容。结合本次主体、情境和视觉重点设计画面，按需交代动作关系、姿势构图、空间、光色、文字和画幅；复杂要求适当分段。

后续反馈只调整相关范围，继续沿用已确认的要求。用户明确满意的部分列为后续保留项，不因其他修改重新设计。角色或其他主体特征以本次参考可见信息和用户设定为依据。多主体任务写清各自属性、位置和互动；图内文字注明准确内容及排版要求。

## 资料与参考分工

只使用本次提供、明确指定或项目规则允许读取的资料。指定系列、画风时，同时读取条目及 `参考/系列/<系列名>-参考索引.md`、`参考/画风/<画风名>-参考索引.md`；旧条目沿用已有有效链接。画风条目用于选图、提取少量重点和验收，不默认作为完整提示词载入。

查看本次选定的原图，按实际接口附图，不要求用户重新上传已有素材。每张参考注明借鉴范围，按实际输入顺序对应；必要补充在首轮加入。参考只提供指定范围内的依据，不自动继承其余内容或表现。

已由底图稳定表达的内容，不重复引入其他参考；需要复核或修复对应特征时再补充。构图等关系能由已确认正文表达时，直接使用该要求；需要精确复刻或用户明确要求时再附相应成图参考。

编辑对象排在第一张，其余输入按分工排列。输入顺序用于明确对应关系，不声称能设置参考权重。工具不能附齐必要输入时说明实际限制，不声称已经附上。

## 画风依据与重点

画风以本次选定的原图为依据，用户明确要求的调整按本次范围执行。主参考提供整体画法，辅助参考补充必要局部；角色、服装、构图等参考分别提供内容。详细分析与原图不一致时，回看原图修正分析，不让旧文字覆盖可见证据。

生图时用简短指令说明采用哪张图的画风，另按实际编号说明各图用途。根据本次需要，点出少量有辨识力、容易丢失或用户明确强调的可见特征；没有必要时可不加重点。不将全部观察项重新拼成画风长段，也不把局部特点扩大到整图。主体、服装、动作和构图独立描述。

例如：“采用图1的整体画风；图2补充浅色布料画法，图3提供角色身份。重点保持图1中主轮廓与内部线条的粗细层级。”详细的线条、色块、阴影和纹理分析留作选图与返图对照，不随提示词发送。用户明确要求纯文字画风或完整分析入词时，按其范围处理。

## 设计发散与收敛

本次需要自主构思时，从用户关键词、指定主题和允许借鉴内容的当前参考出发。区分明确要求、可见线索与模型联想；联想用于创作，不写成已确认的角色设定。用户已定设计或要求局部修改时，仅在允许调整的范围内发散。

1. **提炼设计线索。** 识别角色的标志形状、动势、原有结构、色彩关系及本次给定的设定。按参考分工取用，不从只供画法借鉴的图片继承人物或服装内容。
2. **发散完整构想。** 比较主导概念、整体剪影、体量分布或层次组织明显不同的方向。服装可采用夸张体量、非日常裁片延伸与覆层展开，保持可读的穿着连接和叠压关系；不以常规商品款式为造型上限，也不只更换配色与装饰。
3. **转译并收敛。** 将选定线索转为主体造型，而不止贴附符号。服装中的角色元素应参与裁片走向、开合、体量、连接或纱层组织。选定一个主导构想，其他结构与装饰围绕它形成呼应，舍弃冲突分支，避免逐个堆满所有元素。
4. **提交选定设计。** 自主选定符合角色与本次要求、造型重点明确且结构连贯的一套方案，写清概念如何落实到可见形状与关系。只保存选定结果及简要设计依据，不提交互斥候选或发散过程；常规设计选择不增加候选图调用或用户确认环节。

## 实际提示词组装

保留本次适用的内容系列要求，将新增设计、选定变量和编辑目标分别组织。画风段只保留简短模仿指令与本次少量重点；参考分工按实际附图编号写明，不自动复制画风条目的详细分析。存在可选分支时明确本次采用哪一项，提交前按指令优先级解决冲突，不将互斥要求同时提交。

任务与本次设计补充目标、选定变量和必要保留项，避免在各段重复展开同一套画法或用多组同义词继续加强程度。详细分析是观察和验收依据，提示词只点出本次确需强调的部分。

局部编辑只描述修改目标与必要保留项，不重新展开整张设计或重复载入完整系列正文；已确认的系列结构由底图保留。需要画风原图时继续附图并说明修改区域沿用其画法，不载入完整分析，也不因此扩大为全图重绘。

使用 [compose_prompt.py](../scripts/compose_prompt.py) 生成本版 `.txt`。脚本保留 `--series` 指定的内容正文，去掉首行标题；画风由输入中的 `style.references` 和可选的 `style.highlights` 组装。`--style-notes` 只核验并记录观察笔记路径，不读取或复制笔记内容；`--style` 是该参数的兼容别名，也不再载入全文。脚本不读取参考索引，不替代查看原图、设计和冲突检查。未用的参数省略，局部编辑省略 `--series`。

从工作区执行，路径替换为本次实际文件：

```powershell
$inputSpec = @{
    task = '本次生成或编辑目标'
    images = @(
        @{ path = '参考/画风/画风原图.png'; role = '整体画风基准' }
        @{ path = '项目/<主题>/参考/角色原图.png'; role = '角色身份与外观' }
    )
    style = @{
        references = @(1)
        highlights = @('主轮廓与内部线条保持参考图中的粗细层级')
    }
    design = '本次设计或局部修改目标，以及保留项'
} | ConvertTo-Json -Depth 4
$inputSpec | python -X utf8 "<Skill目录>/scripts/compose_prompt.py" --style-notes "画风/<画风名>.md" --series "系列/<系列名>.md" --output "项目/<主题>/<主题>-<主体>-v版本.txt"
```

通过标准输入传入 JSON；`task`、`design` 为非空文本，`images` 为按实际附图顺序排列的数组，每项包含 `path` 与 `role`。`style.references` 是该数组中画风原图的编号，从 1 开始；编辑时仍按底图在前的完整顺序编号。`style.highlights` 是可省略的简短重点数组，按本次原图与要求选择，不照抄整份分析。直接使用本次提供的画风图时，可不指定 `--style-notes`；没有画风借鉴时省略 `style`。`--series` 可重复。

脚本返回提示词绝对路径、校验摘要、已验证存在的图片路径顺序，以及指定时的观察笔记路径。读取生成的 `.txt` 全文原样作为 `prompt`，按返回顺序实际附图；不把文本文件路径提交给生图工具。观察笔记、索引、历史和文件管理说明不混入提示词。

## 执行与修改范围

首轮直接完成本次内容与表现要求，不预设固定的二次加工流程。参考用于借鉴时生成新图；修改已有成果时明确编辑对象、改变项和保留项。

主要内容、结构或表现体系整体不符时，考虑整体重绘或重新生成；整体方向成立、剩余偏差范围明确时，再采用局部编辑。用户已接受表现、只要求调节某项强弱时，以该版为基准，只改变对应特征的对比、密度、覆盖范围等，保留其他画法。相关问题可以合并处理，无关调整分开进行。

工具参数通过实际开放的字段设置。涉及区域定位、蒙版或其他专门能力时，确认当前接口支持；未开放的能力不能靠提示词替代，也不能声称已经使用。画幅依入口默认规则或本次要求执行，核对实际尺寸；需要透明背景时明确请求并检查真实 alpha 信息。

## 返图验收

依据用户要求、选用预设、参考范围及本轮保留项检查实际结果，不追加助手自己的质量标准。画风先与选定原图对照整体效果和关键关系，再用详细观察笔记辅助检查相关局部；笔记与图不符时以原图及本次明确调整为准。单个特征存在不代表整体表现已成立，不把未发送的分析条目逐项变成硬性要求。

区分明确违背、允许差异和证据不足。用户已接受的差异不反复纠正；无法判断时说明依据不足，不凭猜测反复生成。编辑后同时复核保留项，确认修改没有引入新的偏差。

验收状态使用：

- **通过**：本次必须满足的要求已经满足。
- **局部待修**：主体方向成立，仍有明确区域内的未完成项。
- **整体偏离**：主要内容、结构或表现体系整体不符合本次要求。
- **无法判断**：现有结果或参考不足以作出可靠判断。

结论写明可见依据，区分助手核对结论与用户反馈，不将助手判断写成用户认可。局部未完成不能记为通过；不以提示词已写要求、文件归档成功或调用次数耗尽代替验收。

## 纠偏与停止条件

每轮纠偏明确要解决的问题、采用的改变及预期可见结果，返图后比较实际改善。验证某个原因时固定其余可控制条件；同时改变多项时，不据此认定单一原因。

每个独立成图目标默认首次生成 1 次、自动纠偏最多 2 次，用户明确指定的轮次优先。按实际调用计次，更换提示词、参考或生成与编辑方式不重置次数。

同一问题连续两次纠偏没有可见改善时，停止沿用原策略。达到次数上限后停止自动追加，交付最佳候选、剩余问题和可行的下一步；没有成功返图时说明调用失败，不登记不存在的候选。次数上限不代表验收通过，后续继续按用户要求执行。

本次偏好与偶发问题留在项目中。有明确适用范围的可复用结论，再用于修订通用系列或画风；不将单张失败直接固化为通用视觉标准。未经生成验证的方案标为待验证，不承诺固定成功率。

## 创作记录与实际提示词

实际生图或改图时，在当前项目中分开保存：

- `创作.md`：简记设计结论、采用的预设、实际输入及用途、各版本的目标和编辑底图、实际附图顺序、成图与尺寸、可见改善、验收及反馈。参考集中登记一次，各版本以编号引用；只链接提示词文件，不重复粘贴全文，省略无内容字段。
- `主题-主体-v版本.txt`：本次实际提交给工具的完整 `prompt`，与成图使用相同版本前缀。只含提示词，不混入文件管理说明、分析记录或调用日志。

调用前在 `创作.md` 记下本轮目标、底图、附图顺序和提示词文件，状态标为待生成。返图后补记实际成图、尺寸、验收和实际调用次数；调用失败时保留已提交提示词，记明失败。

已提交的提示词不可覆盖；下一轮另存递增版本，记录实际输入及变化。需要修改尚未提交的文件时，先确认未调用，再重建。记录接口可见的实际文本，不推测内部隐藏改写。

只要求分析、方案、规则更新或提示词时，完成对应交付，不自动生成图片，也不创建虚构的生成记录。
