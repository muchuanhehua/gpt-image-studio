# 创作与反馈

本流程适用于不同主体、画风和编辑任务。具体视觉标准来自本次要求与选定原图；通用规则负责准确组织输入、执行、验收和控制迭代。

## 本次目标

区分用户必须满足的要求、允许自行设计的部分，以及已有成果中需要保留的内容。助手自行选择的姿势、配色和构图细节属于本次方案，不自动升级为用户要求。结合本次主体、情境和视觉重点设计画面，按需交代动作关系、姿势构图、空间、光色、文字和画幅；复杂要求适当分段。

后续反馈只调整相关范围，继续沿用已确认的要求。用户明确满意的部分列为后续保留项，不因其他修改重新设计。角色或其他主体特征以本次参考可见信息和用户设定为依据。多主体任务写清各自属性、位置和互动；图内文字注明准确内容及排版要求。

## 资料与参考分工

用于生图的参考只采用用户本轮上传或明确指定的图片；同一会话内已提供且仍可用的图片可以沿用。指定已有画风时，可读取其观察笔记辅助理解和验收，不自动读取参考索引来选原图，也不从图库追加、补齐或替换用户参考。主体、服装、场景、边框和图案直接依据本次请求设计，不自动加载旧内容预设。

先查看用户提供或指定的实际图片，再按实际接口附图。每张参考注明借鉴范围，按实际输入顺序对应；分工以用户说明与已提供图片为依据，不套用档案索引里的主辅组合。参考只提供指定范围内的依据，不自动继承其余内容或表现。

只给画风名称不等于已经提供原图。任务确需按图模仿而缺少具体参考时，说明所缺图片，待用户上传或明确指定后再进行该项模仿；不以旧库原图自动补位。用户明确要求纯文字画风时按其要求执行，不声称已经附图。

边框、花饰、布局和普通装饰图案默认直接写入本次设计，交代形状、位置、配色、疏密与留白，无需额外参考图。仅当本次明确要求准确复刻指定图形、复杂结构或已有排布时，才按其用途附相应原图；可选元素图不默认成为必须附图。

已由底图稳定表达的内容，不重复引入其他参考；需要复核或修复对应特征时再补充。构图等关系能由文字明确表达时直接使用文字，需要复刻既有空间关系时再附相应成图参考。

编辑对象排在第一张，其余输入按分工排列。输入顺序用于明确对应关系，不声称能设置参考权重。工具不能附齐必要输入时说明实际限制，不声称已经附上。

## 画风依据与重点

画风以用户本次提供或明确指定的原图为依据，用户明确要求的调整按本次范围执行。在已提供图片内区分整体画法、局部画法和角色、服装、构图等用途，不为补充局部画法自行加入库中图片。详细分析与本次原图不一致时，回看原图修正分析，不让旧文字覆盖可见证据。

生图时用简短指令说明采用用户提供的哪张图的画风，另按实际编号说明各图用途。根据本次原图，点出少量有辨识力、容易丢失或用户明确强调的可见特征；没有必要时可不加重点。不将全部观察项重新拼成画风长段，也不把局部特点扩大到整图。主体、服装、动作和构图独立描述。

例如，本轮用户上传画风图1与角色图2时：“采用图1的整体画风，图2提供角色身份。重点保持图1中主轮廓与内部线条的粗细层级。”详细的线条、色块、阴影和纹理分析留作观察与返图对照，不随提示词发送。用户明确要求纯文字画风或完整分析入词时，按其范围处理。

## 设计发散与收敛

用户要求原创设计，或主要造型、构图仍需在不同方向间选择时，从用户关键词、指定主题和允许借鉴内容的当前参考出发，按下述方法构思。主题、主要造型与参考分工已明确时，直接补足完成画面的必要细节，无需额外比较多个概念。区分明确要求、可见线索与模型联想；联想用于创作，不写成已确认的角色设定。用户已定设计或要求局部修改时，仅在允许调整的范围内发散。

1. **提炼设计线索。** 识别角色的标志形状、动势、原有结构、色彩关系及本次给定的设定。按参考分工取用，不从只供画法借鉴的图片继承人物或服装内容。
2. **发散完整构想。** 比较主导概念、整体剪影、体量分布或层次组织明显不同的方向。服装可采用夸张体量、非日常裁片延伸与覆层展开，保持可读的穿着连接和叠压关系；不以常规商品款式为造型上限，也不只更换配色与装饰。
3. **转译并收敛。** 将选定线索转为主体造型，而不止贴附符号。服装中的角色元素应参与裁片走向、开合、体量、连接或纱层组织。选定一个主导构想，其他结构与装饰围绕它形成呼应，舍弃冲突分支，避免逐个堆满所有元素。
4. **提交选定设计。** 自主选定符合角色与本次要求、造型重点明确且结构连贯的一套方案，写清概念如何落实到可见形状与关系。只保存选定结果及简要设计依据，不提交互斥候选或发散过程；常规设计选择不增加候选图调用或用户确认环节。

## 实际提示词组装

以本次目标、改变项和必要保留项组织提示词，按需写明主体、服装、场景、边框与图案。参考已清楚表达的外观交给图片承载，文字补足关键辨识点、变化与容易混淆的关系，不逐项复述可见细节。常见造型可直接使用名称与关键要求，细节决定结果或用户要求精确控制时再展开，不设固定字数。

参考分工按实际附图编号写明；画风段只保留简短模仿指令与本次少量重点。各段分工明确，避免重复描述同一外观、画法或排除内容，也不用多组同义词继续加强程度。详细分析留作观察和验收。存在可选分支时选定本次方案，提交前按指令优先级解决冲突，不将互斥要求同时提交。

局部编辑只描述修改目标与必要保留项，不重新展开整张设计；已确认的结构由底图保留。需要画风原图时继续附图并说明修改区域沿用其画法，不载入完整分析，也不因此扩大为全图重绘。

使用 [compose_prompt.py](../scripts/compose_prompt.py) 生成本版 `.txt`。内容全部来自本次输入的 `task` 与 `design`，不自动载入内容预设文件；画风由输入中的 `style.references` 和可选的 `style.highlights` 组装。`--style-notes` 只核验并记录观察笔记路径，不读取或复制笔记内容；`--style` 是该参数的兼容别名，也不载入全文。脚本不读取参考索引，不替代查看原图、设计和冲突检查。未用的参数省略。

从工作区执行，路径替换为本次实际文件：

```powershell
$inputSpec = @{
    task = '本次生成或编辑目标'
    images = @(
        @{ path = '项目/<主题>/参考/画风-用户提供-01.png'; role = '本轮用户提供的整体画风基准' }
        @{ path = '项目/<主题>/参考/角色原图.png'; role = '角色身份与外观' }
    )
    style = @{
        references = @(1)
        highlights = @('主轮廓与内部线条保持参考图中的粗细层级')
    }
    design = '本次主体、服装和动作；边框为细线拱顶、下角小花簇，顶部中央画一个简洁水滴线描图案。局部编辑另写修改目标与保留项。'
} | ConvertTo-Json -Depth 4
$inputSpec | python -X utf8 "<Skill目录>/scripts/compose_prompt.py" --output "项目/<主题>/<主题>-<主体>-v版本.txt"
```

通过标准输入传入 JSON；`task`、`design` 为非空文本，`images` 只登记用户本次提供或明确指定的图片，按实际附图顺序排列，每项包含 `path` 与 `role`。`style.references` 是该数组中画风原图的编号，从 1 开始，不是归档索引编号；编辑时仍按底图在前的完整顺序编号。`style.highlights` 是可省略的简短重点数组，按本次原图与要求选择，不照抄整份分析。有明确指定的观察笔记时可选用 `--style-notes`，不据此查找或添加原图；没有画风借鉴时省略 `style`。没有图片输入时可省略 `images`，直接提交文字设计。

脚本返回提示词绝对路径、校验摘要、已验证存在的图片路径顺序，以及指定时的观察笔记路径。读取生成的 `.txt` 全文原样作为 `prompt`，按返回顺序实际附图；不把文本文件路径提交给生图工具。观察笔记、索引、历史和文件管理说明不混入提示词。

## 执行与修改范围

首轮直接完成本次内容与表现要求，不预设固定的二次加工流程。参考用于借鉴时生成新图；修改已有成果时明确编辑对象、改变项和保留项。

主要内容、结构或表现体系整体不符时，考虑整体重绘或重新生成；整体方向成立、剩余偏差范围明确时，再采用局部编辑。用户已接受表现、只要求调节某项强弱时，以该版为基准，只改变对应特征的对比、密度、覆盖范围等，保留其他画法。相关问题可以合并处理，无关调整分开进行。

工具参数通过实际开放的字段设置。涉及区域定位、蒙版或其他专门能力时，确认当前接口支持；未开放的能力不能靠提示词替代，也不能声称已经使用。画幅依入口默认规则或本次要求执行，核对实际尺寸；需要透明背景时明确请求并检查真实 alpha 信息。

## 返图验收

依据用户要求、参考范围及本轮保留项检查实际结果，不追加助手自己的质量标准。验收精度与本次用途相称：例如“纯色背景”先检查视觉上是否为单一背景、有无明显渐变或场景；用户或交付规格要求精确色值、尺寸时，再以对应的像素检查作为硬门槛。记录实际尺寸与目标比例的差异，明显比例偏离需要纠正，视觉不可辨的像素取整误差不单独触发重绘。

画风先与选定原图对照整体效果和关键关系，再用详细观察笔记辅助检查相关局部；笔记与图不符时以原图及本次明确调整为准。单个特征存在不代表整体表现已成立，不把未发送的分析条目逐项变成硬性要求。

区分明确违背、允许差异和证据不足。用户已接受的差异不反复纠正；无法判断时说明依据不足，不凭猜测反复生成。编辑后同时复核保留项，确认修改没有引入新的偏差。

验收状态使用：

- **通过**：本次必须满足的要求已经满足。
- **局部待修**：主体方向成立，仍有明确区域内的未完成项。
- **整体偏离**：主要内容、结构或表现体系整体不符合本次要求。
- **无法判断**：现有结果或参考不足以作出可靠判断。

结论写明可见依据，区分助手核对结论与用户反馈，不将助手判断写成用户认可。局部未完成不能记为通过；不以提示词已写要求、文件归档成功或调用次数耗尽代替验收。

## 纠偏与停止条件

每轮纠偏明确要解决的问题、采用的改变及预期可见结果，返图后比较实际改善。验证某个原因时固定其余可控制条件；同时改变多项时，不据此认定单一原因。

每个独立成图目标默认首次生成 1 次、自动纠偏最多 2 次，用户明确指定的轮次优先。次数是上限；本次必须满足的要求已满足时即交付。自动纠偏针对用户要求、参考分工或必要保留项的明确违背，不为追求助手自加的精度或方案细节继续生成。按实际调用计次，更换提示词、参考或生成与编辑方式不重置次数。

同一问题连续两次纠偏没有可见改善时，停止沿用原策略。达到次数上限后停止自动追加，交付最佳候选、剩余问题和可行的下一步；没有成功返图时说明调用失败，不登记不存在的候选。次数上限不代表验收通过，后续继续按用户要求执行。

本次设计、偏好与偶发问题留在项目中。有明确适用范围的画法观察结论，再用于修订画风笔记；不将单张失败直接固化为通用视觉标准。未经生成验证的方案标为待验证，不承诺固定成功率。

## 创作记录与实际提示词

实际生图或改图时，在当前项目中分开保存：

- `创作.md`：简记设计结论、本次画风、用户提供或指定的实际输入及用途、各版本的目标和编辑底图、实际附图顺序、成图与尺寸、可见改善、验收及反馈。参考集中登记一次，各版本以编号引用；只链接提示词文件，不重复粘贴全文，省略无内容字段。
- `主题-主体-v版本.txt`：本次实际提交给工具的完整 `prompt`，与成图使用相同版本前缀。只含提示词，不混入文件管理说明、分析记录或调用日志。

调用前在 `创作.md` 记下本轮目标、底图、附图顺序和提示词文件，状态标为待生成。返图后补记实际成图、尺寸、验收和实际调用次数；调用失败时保留已提交提示词，记明失败。

已提交的提示词不可覆盖；下一轮另存递增版本，记录实际输入及变化。需要修改尚未提交的文件时，先确认未调用，再重建。记录接口可见的实际文本，不推测内部隐藏改写。

只要求分析、方案、规则更新或提示词时，完成对应交付，不自动生成图片，也不创建虚构的生成记录。
