# 创作与反馈

本流程适用于不同主体、系列、画风和编辑任务。具体视觉标准来自本次要求与选用预设；通用规则负责准确组织输入、执行、验收和控制迭代。

## 本次目标

区分必须满足的要求、允许自行设计的部分，以及已有成果中需要保留的内容。结合本次主体、情境和视觉重点设计画面，按需交代动作关系、姿势构图、空间、光色、文字和画幅；复杂要求适当分段。

后续反馈只调整相关范围，继续沿用已确认的要求。用户明确满意的部分列为后续保留项，不因其他修改重新设计。角色或其他主体特征以本次参考可见信息和用户设定为依据。多主体任务写清各自属性、位置和互动；图内文字注明准确内容及排版要求。

## 资料与参考分工

只使用本次提供、明确指定或项目规则允许读取的资料。指定系列、画风时，同时读取正文及 `参考/系列/<系列名>-参考索引.md`、`参考/画风/<画风名>-参考索引.md`；旧条目沿用已有有效链接。

查看本次选定的原图，按实际接口附图，不要求用户重新上传已有素材。每张参考注明借鉴范围，按实际输入顺序对应；必要补充在首轮加入。参考只提供指定范围内的依据，不自动继承其余内容或表现。

已由底图稳定表达的内容，不重复引入其他参考；需要复核或修复对应特征时再补充。构图等关系能由已确认正文表达时，直接使用该要求；需要精确复刻或用户明确要求时再附相应成图参考。

编辑对象排在第一张，其余输入按分工排列。输入顺序用于明确对应关系，不声称能设置参考权重。工具不能附齐必要输入时说明实际限制，不声称已经附上。

## 实际提示词组装

完整保留本次适用的已确认规则，将新增设计、选定变量和编辑目标分别组织。指定已有画风时，其正文保持为独立段，不在组装时摘要、改写或翻译；只借部分或明确改变预设时按用户范围取用。存在可选分支时明确本次采用哪一项，提交前按指令优先级解决冲突，不将互斥要求同时提交。

画风正文承担通用画法；任务、参考分工和本次设计补充目标、借鉴范围、选定变量与必要保留项，避免在各段重复展开同一套画法或用多组同义词继续加强程度。

局部编辑只描述修改目标与必要保留项，不重新展开整张设计或重复载入完整系列正文；已确认的系列结构由底图保留。修改区域仍需保持的表现规则与必要依据继续沿用；完整画风正文作为修改区域的表现约束，不构成全图重绘要求。

使用 [compose_prompt.py](../scripts/compose_prompt.py) 直接读取预设正文生成本版 `.txt`，避免手工转抄。脚本去掉预设首行标题，保留其余正文；不读取参考索引，也不替代查看原图、设计和冲突检查。未用的预设参数省略，局部编辑省略 `--series`。

从工作区执行，路径替换为本次实际文件：

```powershell
$inputSpec = @{
    task = '本次生成或编辑目标'
    images = @(@{ path = '参考/类别/原图.png'; role = '本图的借鉴范围' })
    design = '本次设计或局部修改目标，以及保留项'
} | ConvertTo-Json -Depth 4
$inputSpec | python -X utf8 "<Skill目录>/scripts/compose_prompt.py" --style "画风/<画风名>.md" --series "系列/<系列名>.md" --output "项目/<主题>/<主题>-<主体>-v版本.txt"
```

通过标准输入传入 JSON；`task`、`design` 为非空文本，`images` 为按实际附图顺序排列的数组，每项包含 `path` 与 `role`。可用 `style_settings` 明确正文允许的本次变化；`--series` 可重复。

脚本返回提示词绝对路径、校验摘要和已验证存在的图片路径顺序。读取生成的 `.txt` 全文原样作为 `prompt`，按返回顺序实际附图；不把文本文件路径提交给生图工具。索引、历史和文件管理说明不混入提示词。

## 执行与修改范围

首轮直接完成本次内容与表现要求，不预设固定的二次加工流程。参考用于借鉴时生成新图；修改已有成果时明确编辑对象、改变项和保留项。

主要内容、结构或表现体系整体不符时，考虑整体重绘或重新生成；整体方向成立、剩余偏差范围明确时，再采用局部编辑。用户已接受表现、只要求调节某项强弱时，以该版为基准，只改变对应特征的对比、密度、覆盖范围等，保留其他画法。相关问题可以合并处理，无关调整分开进行。

工具参数通过实际开放的字段设置。涉及区域定位、蒙版或其他专门能力时，确认当前接口支持；未开放的能力不能靠提示词替代，也不能声称已经使用。画幅依入口默认规则或本次要求执行，核对实际尺寸；需要透明背景时明确请求并检查真实 alpha 信息。

## 返图验收

依据用户要求、选用预设、参考范围及本轮保留项检查实际结果，不追加助手自己的质量标准。先核对全图的整体效果和关键关系，再检查与本轮目标或偏差有关的局部；单个特征存在不代表整体表现已成立。需要对照参考时核对其指定借鉴范围。

区分明确违背、允许差异和证据不足。用户已接受的差异不反复纠正；无法判断时说明依据不足，不凭猜测反复生成。编辑后同时复核保留项，确认修改没有引入新的偏差。

验收状态使用：

- **通过**：本次必须满足的要求已经满足。
- **局部待修**：主体方向成立，仍有明确区域内的未完成项。
- **整体偏离**：主要内容、结构或表现体系整体不符合本次要求。
- **无法判断**：现有结果或参考不足以作出可靠判断。

结论写明可见依据，区分助手核对结论与用户反馈，不将助手判断写成用户认可。局部未完成不能记为通过；不以提示词已写要求、文件归档成功或调用次数耗尽代替验收。

## 纠偏与停止条件

每轮纠偏明确要解决的问题、采用的改变及预期可见结果，返图后比较实际改善。验证某个原因时固定其余可控制条件；同时改变多项时，不据此认定单一原因。

每个独立成图目标默认首次生成 1 次、自动纠偏最多 2 次，用户明确指定的轮次优先。按实际调用计次，更换提示词、参考或生成与编辑方式不重置次数。

同一问题连续两次纠偏没有可见改善时，停止沿用原策略。达到次数上限后停止自动追加，交付最佳候选、剩余问题和可行的下一步；没有成功返图时说明调用失败，不登记不存在的候选。次数上限不代表验收通过，后续继续按用户要求执行。

本次偏好与偶发问题留在项目中。有明确适用范围的可复用结论，再用于修订通用系列或画风；不将单张失败直接固化为通用视觉标准。未经生成验证的方案标为待验证，不承诺固定成功率。

## 创作记录与实际提示词

实际生图或改图时，在当前项目中分开保存：

- `创作.md`：简记设计结论、采用的预设、实际输入及用途、各版本的目标和编辑底图、实际附图顺序、成图与尺寸、可见改善、验收及反馈。参考集中登记一次，各版本以编号引用；只链接提示词文件，不重复粘贴全文，省略无内容字段。
- `主题-主体-v版本.txt`：本次实际提交给工具的完整 `prompt`，与成图使用相同版本前缀。只含提示词，不混入文件管理说明、分析记录或调用日志。

调用前在 `创作.md` 记下本轮目标、底图、附图顺序和提示词文件，状态标为待生成。返图后补记实际成图、尺寸、验收和实际调用次数；调用失败时保留已提交提示词，记明失败。

已提交的提示词不可覆盖；下一轮另存递增版本，记录实际输入及变化。需要修改尚未提交的文件时，先确认未调用，再重建。记录接口可见的实际文本，不推测内部隐藏改写。

只要求分析、方案、规则更新或提示词时，完成对应交付，不自动生成图片，也不创建虚构的生成记录。
