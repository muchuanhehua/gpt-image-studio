# 创作与反馈

## 画面设计

结合本次主题、角色、视觉重点和明确指定的系列或画风，设计完整画面。按需交代主体、场景、动作关系、姿势构图、光色、画幅和约束；复杂画面适当分段。

角色以参考图可见特征和用户设定为依据。换装时保留身份特征，服装、姿态、道具和情绪适配本次主题。

保留用户具体设计，补足服务于目标的细节。属性跟随所属对象，多人图写清位置和互动；图内文字逐字注明，排版要求另写。

## 读取与参考分工

读取本次指定的系列、画风正文及其参考索引：`参考/系列/<系列名>-参考索引.md`、`参考/画风/<画风名>-参考索引.md`；旧条目沿用已有的有效链接。查看选定的本地原图，按实际接口附图，不要求用户重新上传已有素材。

画风主参考提供整体画法；补充参考只提供注明的材质或局部画法。选择时先覆盖本次主要材质与明暗表现，再考虑描边色系，不只按配色选图。必要补充在首轮加入，不等偏离后才补。角色、元素、构图参考分别限定借鉴范围；指定画风时，这些参考中的画法不作为渲染依据。

构图能由已确认的正文表达时，默认直接使用布局要求，不额外附整张历史成图。确需精确复刻空间关系或用户明确要求时再附构图图，并限定借鉴范围；不删除原有归档。

确定输入顺序后逐图写明用途。编辑对象排在第一张；新图可先列画风主参考与必要补充，再列角色和元素，便于核对分工。顺序用于明确对应关系，不声称能设置参考权重。

## 实际提示词组装

指定已有画风时，完整保留其正文为独立画风段，不在组装时摘要、改写或翻译。系列正文另成内容段。本次角色、服装、道具、构图及选定的画风变化另写；检查是否与画风要求冲突。用户明确只借部分或要求改变画风时按其范围取用，并在记录中说明。

使用 [compose_prompt.py](../scripts/compose_prompt.py) 直接读取预设正文生成本版 `.txt`，避免手工转抄。脚本去掉预设首行标题，保留其余正文；不读取参考索引，也不替代查看原图、设计和冲突检查。没有预设时同样可用，省略对应参数。

从工作区执行，路径替换为本次实际文件：

```powershell
$inputSpec = @{
    task = '本次生成或编辑目标'
    images = @(@{ path = '参考/类别/原图.png'; role = '本图的借鉴范围' })
    design = '本次角色、服装、构图与保留项'
} | ConvertTo-Json -Depth 4
$inputSpec | python -X utf8 "<Skill目录>/scripts/compose_prompt.py" --style "画风/<画风名>.md" --series "系列/<系列名>.md" --output "项目/<主题>/<主题>-<主体>-v版本.txt"
```

通过标准输入传入 JSON；`task`、`design` 为非空文本，`images` 为按实际附图顺序排列的数组，每项包含 `path` 与 `role`。可用 `style_settings` 选定正文允许的变化；编辑时在 `task` 和 `design` 中写清修改与保留项。`--series` 可重复，未用的预设参数省略。

脚本返回提示词绝对路径、校验摘要及已验证存在的图片路径顺序。读取生成的 `.txt` 全文原样作为 `prompt`，按返回顺序实际附图；不把文本文件路径提交给生图工具。模型、质量等仅按真实工具字段设置，提示词或脚本均不能代替未开放的接口参数。

## 生成与编辑

参考图用于借鉴时生成新图；修改已有成图时，将其作为编辑对象。画幅遵循入口默认规则或用户明确要求；尺寸目标依工具能力执行。需要透明背景时明确请求，并检查实际 alpha 信息。

局部修改沿用已确认的画风正文、选定原图与参考分工，重新附上编辑底图和必要画风原图。明确只改哪些结构、保留哪些设计，同时保留描线、渐变、阴影和纹理规则，不只写“保持原画风”。工具不能附齐必要输入时说明实际限制，不声称已经附上。

不预设“先出设计、第二次套画风”为默认流程。首轮直接完成本次内容与画风要求。

## 创作记录与实际提示词

实际生图或改图时，在当前项目中分开保存：

- `创作.md`：简记设计结论、采用的系列与画风、参考文件及用途、各版本的目标、编辑底图、实际附图顺序、成图与尺寸、验收结果和用户反馈。参考文件集中登记一次，各版本以编号引用；只链接提示词文件，不重复粘贴全文，省略无内容字段。
- `主题-主体-v版本.txt`：本次实际提交给工具的完整 `prompt`，与成图使用相同版本前缀。只含提示词，不混入文件管理说明、分析记录或调用日志。

调用前在 `创作.md` 记下本轮目标、底图、附图顺序和提示词文件，状态标为待生成。返图后保存实际成图并补记尺寸与验收。调用失败时保留已提交提示词，记明失败，不登记不存在的成图。

已提交的提示词不可覆盖；下一轮另存递增版本，记录实际输入及变化。需要修改尚未提交的文件时，先确认未调用，再重建；不改已提交原文。记录接口可见的实际文本，不推测内部隐藏改写。

只要求分析、方案、规则更新或提示词时，完成对应交付，不自动生成图片，也不创建虚构的生成记录。

## 返图验收与反馈

交付前把实际返图与本次画风原图并排对照，同时查看全图与头发、脸、主要衣料等关键局部。分别判断：

- 用户要求、角色身份、姿势构图、文字和编辑保留项是否满足。
- 主要轮廓、内部结构线与装饰线是否保留预设的粗细、颜色、提按和对比层级。
- 渐变、主阴影边界、各材质的光泽或哑光表现是否符合所选画风。
- 纹理的分布和密度是否符合预设，细节是否压过主要形体。

记录画风“通过／未通过／无法判断”，有偏差时写明可见位置和表现，不以“已写进提示词”或“文件归档成功”代替画风通过。局部修改同时复核未修改部分的画法，防止结构修正引起风格偏移。

明显偏离时不能标为完成；需要纠偏时按本次授权执行并如实记录实际调用次数与改动，不隐去重试，也不把第二次结果称作首轮成功。没有生图验证的调用方案标为待验证，不承诺固定首轮成功率。

根据用户满意与需改的部分，联合实际返图、提示词和附图判断原因，保留有效设计。多项同时变化的两轮结果不能用于认定单一原因；验证某项改动时固定其余可控制条件。单张偶发瑕疵不直接改写通用画风，本次偏好记在项目中。
